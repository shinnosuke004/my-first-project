# gcal-sync: GCal(Movie/Book)→ Craft(映画/本)同期

ユーザーが「同期」を押した(呼び出した)ときに実行する。**確認を挟まずに最後まで実行**してよい(ユーザーが押したこと自体が実行の指示)。
ただし次の「安全の決まり」は必ず守る。

## 安全の決まり
- **追加のみ。** Craftの既存の行は、編集・削除・移動しない。
- **二重取り込みをしない。** 下記の重複判定で既存と一致した予定は飛ばす。
- **未来の予定は取り込まない。** 日付が今日(JST)より後の予定は無視する。
- 想定外のこと(スキーマが違う、カレンダーが読めない等)が起きたら、**書き込まずに止めて報告**する。

## 対応表
| GCalカレンダー | calendarId | Craft collection | collection ID |
|---|---|---|---|
| Movie | `1qqikio6rgqbahqnkkjg08bi78@group.calendar.google.com` | 映画(☑️映画ログ(統合)) | `fd53b864-be3a-2b9a-c1b1-de9b3a940135` |
| Book | `untd9gpl37ubpg13pq0p3tm7jk@group.calendar.google.com` | 本(☑️本ログ(統合)) | `6a3be8c5-ce08-4496-1563-00dd0ee6023a` |

使うツール: Craft は `mcp__craft_database__craft_read` / `mcp__craft_database__craft_write`、GCal は `mcp__Google_Calendar__list_events`。
ツールが未読み込みなら、ToolSearch で `select:` 指定して読み込む。

Craftのcollectionの列は次のとおり(順序もこのとおり): **タイトル → ジャンル → 評価 → ステータス → 年 → 完了日**。
列のキー(`_3` など)は変わる可能性があるため、**毎回 `collections schema --collection <ID>` で、タイトル・ステータス・年・完了日の4列のキーを確認**してから書き込む。
(2026-10時点: タイトル=`_6`、ステータス=`_3`、年=`_4`、完了日=`_5`。ジャンルのキーは空文字で、使わない)

## 手順(映画・本それぞれについて、同じ手順を行う)

### 1. Craftの既存の行を全件読む
`collections items-get --collection <ID> --depth 0 --page-size 200 --format markdown`
- 結果に `more available` と `--cursor` が出たら、`--cursor` を付けて**最後まで**読む。
- 各行から「タイトル」と「完了日」を取り出す。
- **最新の完了日**(最大値)を求める。これを `since` とする。
- 既存タイトルは**正規化**して比較用に持つ: 前後の空白を削り、末尾の「 (MM/DD, ...)」「※...」のような補足部分を取り除く。

### 2. GCalの予定を読む
`list_events` を次の条件で呼ぶ。
- calendarId: 対応表のとおり
- startTime: `since` の 00:00 JST(例: `2025-10-24T00:00:00+09:00`)
- endTime: **明日の 00:00 JST**(今日の予定を含めるため)
- orderBy: `startTime`、pageSize: 250、timeZone: `Asia/Tokyo`
- `nextPageToken` があれば、最後まで読む。

予定ごとに次を作る。
- **タイトル** = `summary`(前後の空白を削る)
- **完了日** = `start` の日付(JST)。`start.dateTime` なら日付部分、`start.date` ならその日付。
- **年** = 完了日の年(4桁)
- `status` が `cancelled` の予定は無視する。
- 完了日が今日(JST)より後の予定は無視する。

### 3. 重複を除く
GCalの予定の「正規化したタイトル + 完了日」が、Craftの既存の行の「正規化したタイトル + 完了日」と**一致したら飛ばす**。
GCal側の中でも、タイトルと完了日が同じ予定が複数あれば1件にする。

### 4. 追加する
残った予定を、1つのcollectionにつき1回の `items-add` でまとめて追加する。

```
collections items-add --collection <ID> --allow-new-options --items '[{"<タイトルのキー>":"作品名","properties":{"<ステータスのキー>":"完了","<年のキー>":"2026","<完了日のキー>":"2026-09-30"}}]'
```

- ステータスは常に「完了」。ジャンル・評価は空欄のまま(推測しない)。
- タイトルに半角のシングルクォート `'` がある場合は、`'\''` に置き換えてJSONを壊さない。
- 追加が0件なら、`items-add` は呼ばない。

### 5. 検証
追加後、`collections list --document <ドキュメントID>` などで件数を確認し、**追加前の件数 + 追加件数 = 追加後の件数** になっているか確かめる。合わなければ、そのことを報告する(自動で削除して直そうとしない)。

### 6. 報告
映画・本それぞれについて、次を表示する。
- 取得した予定の件数 / 追加した件数 / 重複で飛ばした件数 / 未来のため無視した件数
- 追加した行の一覧(タイトルと完了日)
- 検証の結果(件数が合ったか)

## メモ
- 取得範囲は「最新の完了日」以降のみ。それより前の日付で、あとからGCalに追加された予定は拾えない。必要なら、ユーザーに「全期間を見る」かを確認してから、`since` を指定し直す。
- 将来の拡張案(未実装): 未来の予定を「視聴予定」「購入予定」で追加する、ジャンルや評価の入力補助。
